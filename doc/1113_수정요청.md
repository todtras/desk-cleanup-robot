# 11/13 수정 요청 (UI 팀)

진짜 로봇 쪽(`real_cleaner.py`)은 팀장이 이미 바꿨다. 아래는 화면과 가짜 로봇에 맞춰 넣어야 하는 것.

## 1. 설정: 집는 순서 (`order`)

**왜:** 5종을 한꺼번에 두고 정리하면, 다른 물체를 먼저 집으러 가다가 물병에 팔이 걸린다. 키 큰 물체부터 집도록 우선순위를 둔다.

**설정 값**
- 이름: `order`
- 형식: 물체 이름 목록, 앞에 있는 것부터 집음. 같은 종류가 여러 개면 신뢰도 높은 것부터
- 기본값: `["bottle", "tape", "eraser", "pen", "paper"]` (물병 → 테이프 → 지우개 → 펜 → 종이, 키 큰 순서)
- 저장: 지금 API 그대로 `PUT /api/settings`에 `{"order": [...]}`를 보내면 됨 (서버는 이미 받음)

**A (서버 · 가짜 로봇)**
- `cleaner.py`의 `DEFAULT_SETTINGS`에 `"order"` 기본값 추가
- `FakeCleaner`도 다음에 집을 물체를 고를 때 `order` 순서를 따르게 (지금은 다른 기준). 진짜 로봇과 같은 순서로 움직여야 화면 시험이 실제와 맞음
- 가이드 3-1(API) 설정 항목 표에 `order` 추가

**B (화면)**
- `settings.html`에 "집는 순서" 항목 추가. 물체 목록을 위아래로 옮기는 버튼(▲▼) 정도면 충분
- 꺼 둔 물체(설정의 물체 켜기/끄기)는 목록에 회색으로 표시
- "기본값으로" 버튼이 있으면 위 기본 순서로 되돌림

**확인:** 순서를 바꾸고 저장 → 새로고침해도 유지 → 가짜 로봇이 그 순서로 집는지

## 2. 새 물체 3종: 공장 부품

**왜:** 프로젝트를 "ACT 기반 웨어하우스 관리 시스템"으로 확장한다. 유스케이스가 사무용품 정리(기존 5종)와 **공장 부품 분류** 두 가지가 된다. 부품은 계단 모양이고 길이가 세 가지다.

**YOLO 클래스 이름 (코드와 데이터에서 쓰는 이름)**

| 클래스 | 화면 표시 (제안) | 수거함 (제안) |
|---|---|---|
| `stepS` | 짧은 부품 | 부품 A |
| `stepM` | 중간 부품 | 부품 B |
| `stepL` | 긴 부품 | 부품 C |

- Roboflow는 클래스를 알파벳순으로 번호를 매긴다 (bottle, eraser, paper, pen, stepL, stepM, stepS, tape). 라벨링할 때는 번호가 아니라 **이름**으로 고를 것
- 라벨링용 사진: 팀장 노트북 `dev/outputs/yolo_step/` (길이별 폴더, 45장씩, 따로 전달)

**A (서버 · 가짜 로봇)**
- `cleaner.py`의 물체 이름(`OBJECTS`)과 수거함(`BINS`)에 위 3종 추가
- 가짜 로봇 녹화 영상에는 부품이 없으니, 화면 시험은 이름·설정 표시까지만

**B (화면)**
- 설정 화면의 물체 켜기/끄기, 집는 순서 목록에 3종이 보이게
- 사무용품과 부품을 **두 묶음**(유스케이스별)으로 나눠 보여 주면 좋음: 예) "사무용품 정리" / "부품 분류" 탭 또는 제목

**확인:** 설정 화면에 8종이 두 묶음으로 보이고, 켜고 끄기와 순서 저장이 되는지

## 3. 참고 (할 일 없음)

- 로봇이 정리를 시작할 때 **처음 1초는 천천히 출발**한다 (갑자기 빠르게 움직이는 문제 때문). 화면 진행 표시를 만들 때 참고
- 정책이 물체를 다시 보는 간격이 바뀌었다 (내부 동작). 화면·API에는 영향 없음
- 설정에 `mask_others`(기본 `true`)가 생겼다: 여러 물체가 있을 때 로봇이 지금 집는 물체 외의 물체를 정책 입력 화면에서 지운다. 사용자 설정 화면에 넣을 필요는 없음 (A는 `DEFAULT_SETTINGS`에 넣지 않아도 됨)
